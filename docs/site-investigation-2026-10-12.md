# 네 상품 조사 및 0.1.18 검증

조사일: 2026-10-12 (한국 시간). 로컬 Mac 파일 접근, Git fetch, Chrome 실행 권한과 Playwright `headless: false` 실행을 직접 확인했다. 최초 확인한 main과 origin/main은 ca49a56이었다. 기존 작업 파일은 깨끗했으며 클라우드 미커밋 수정안을 가져왔다고 가정하지 않았다.

별도 Chrome 지속 프로필은 저장소 밖에 두었다. 조사 도구가 한 번 재시작되어 같은 프로필로 재실행했고, 최종 이동에서 로그인이 필요해 사용자가 다시 로그인했다. 이후 아래 실제 코드 검증은 재로그인한 동일 Chrome 인스턴스와 프로필에서 수행했다. 내장 브라우저는 실제 탭을 도구로 연결한 뒤 빕스·의원 최종 화면 구조를 확인하는 데에도 사용했다. 내장 브라우저의 로그인과 별도 Chrome 로그인을 공유하거나 쿠키를 옮기지 않았다.

## 실제 콘텐츠 스크립트 검증

소스의 composition/stages/slots/form/party/restaurant/content를 Playwright의 문서 초기 스크립트로 주입해 첫 진입부터 최종 입력까지 실행했다. 실제 사이트의 React 화면 전환·버튼·입력란을 사용했다. Chrome 확장 저장소와 메시지는 검증용 객체로 대체해 작업 상태를 문서 이동 사이에도 유지했다. `autoConfirm: false`였고, 최종 신청·결제 버튼의 클릭을 별도로 차단하는 캡처 핸들러도 설치했다.

네 경로 모두 최종 추가정보 적용 후 중지 결과를 반환했고, 최종 버튼 클릭 이벤트는 0회였다. 로그인 정보·쿠키·예약자 연락처는 출력하거나 저장하지 않았다. 실제 예약 신청·결제·예약 성공 여부는 검증하지 않았다. Chrome에 설치한 확장의 서비스 워커와 팝업을 포함한 전체 런타임 검증도 아니다.

## 재현 테스트

- `npm test`: 80개 Node 테스트. 탭·작업·날짜·스캔 식별, 중복 신청 잠금, 단계 적용 기록, 설정 범위, 인원 합계, 월 경계, 필수 정보 변경 시 중지를 검증했다.
- `npm run check`: 콘텐츠 스크립트·팝업·서비스 워커의 문법 검사 통과.
- `npm run verify:browser`: 화면이 보이는 로컬 Chrome에서 18개 검사. 공개 DOM 조각으로 인원 구성 식별 속성 제거, 정확한 수량 적용, 추가 인원 분리, 필수 옵션/추가정보/동의 입력, 항목 제거·중지·새 필수 입력 발견을 검증했다. 실제 popup.html/popup.js를 격리된 저장소·메시지 객체와 실행해 버튼 아래 표시, 성공·오류 메시지, 단계별 저장 및 설정 보존을 확인했다. 가짜 요청 페이지에서 자동 신청이 켜져 있어도 결제 버튼을 누르지 않는 것을 검증했다.

`tests/fixtures`에는 공개 수량·옵션·추가정보 영역만 저장했다. SVG는 제거했으며 예약자 정보·쿠키·페이지 전체 HTML은 포함하지 않는다. 재현 화면의 이벤트 처리는 검사용으로 작성했으므로 실제 서버 검증과 구분해야 한다.

## 코드 리뷰와 제한

구현 후 자체 코드 리뷰에서 다른 팝업의 상품 설정을 오래된 저장소 값으로 덮어쓸 위험, 다음 달 날짜의 중복, 저장한 중간 단계가 사라졌는데 최종 화면까지 진행하는 문제를 수정했다. 인원 구성·중간 단계·최종 입력 저장은 분리되며, 실행 중 각 단계 적용 기록을 작업/탭/날짜/스캔과 결합한다. 최종 화면에서 미적용 단계가 있으면 중지한다.

예약 진입 버튼이 클릭 처리 준비 전에 표시되는 경우 재시도하며, 최종 입력 항목이 준비될 때까지 기다린 뒤 비교한다. 이를 재현 검사와 실제 경로에서 확인했다.

사이트가 필수 항목을 완전히 다른 구조로 표시하면 추가 대응이 필요하다. 인식 실패·비활성 수량·항목 변경 시 대체값을 선택하지 않는다. 기존 인원 구성/최종 추가정보 저장 형식은 유지했지만 의원의 임의 기본값은 제거했으므로 해당 상품의 첫 옵션과 최종 입력을 다시 저장해야 한다. 결제는 항상 사용자가 직접 완료한다.
