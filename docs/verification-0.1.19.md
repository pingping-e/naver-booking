# 0.1.19 후속 검증

2026-10-12, 로컬 Mac. `git fetch`로 시작 시 main/origin/main의 a4ff55b(0.1.18)을 확인했으며 작업 파일은 깨끗했다. 쿠키·로그인 정보는 출력하거나 Git에 저장하지 않았다.

## 재현된 실제 오류와 수정

사용자의 Chrome에서 확장 팝업을 직접 확인했다. 빕스의 인원 구성은 저장되어 있었으나 최종 추가정보 설정이 없어 “현재 화면에서 불러와 저장하세요”라는 이유로 중지했다. 단일 확인·동의까지 사전 저장을 요구한 것이 이번 오류의 직접 원인이었다.

- 필수 단일 선택·체크는 저장 없이 자동 처리한다. 복수 선택·직접 입력·수량은 사용자가 지정한다. 비활성 대안이 있다고 단일 답으로 간주하지 않는다.
- 목록을 열어 실제 선택지를 읽고 선택값을 변경하지 않은 채 닫는다. “선택해 주세요.”는 값으로 저장하지 않는다. 복수 선택지는 팝업 목록에서 고른다.
- 직접 연 최종 화면에서도 확인 항목을 자동 처리한다. 미설정 항목·적용 오류는 화면 아래에 표시한다. 저장한 값이 사라지면 대체하지 않는다.
- 최종 링크도 같은 상품 주소로 정규화한다. 완료된 경로의 수량·회차 매개변수는 감시 시작에 사용하지 않는다.
- 사전 설정은 나타나는 중간 화면을 순서대로 기록한다. 각 화면의 값은 별도 저장하며 같은 제목이라도 항목이 다르면 분리한다. 경로 완주·필요한 값 준비 후 감시하며 실행 중 순서와 항목·선택지를 대조한다.
- 실제 인원 변경은 `gbwState`를 갱신한다. 이를 화면 이탈로 오인했던 수동 적용·사전 설정 오류를 수정했다. 수량 적용 직후 다음 버튼 활성화를 기다린다.
- 같은 문서에서 시간 선택 후 저장소의 최신 선택 시간을 조회한다. 비욘더팜의 최종 주소는 날짜를 `00:00`으로 표시하지만 화면은 `오후 7:00`이다. 이 경우에는 화면의 유일한 회차 표시가 선택한 시간과 같은지 확인한다.

## 실제 사이트: 설치한 확장 전체 런타임

Playwright `headless:false`와 저장소 밖의 동일 지속 프로필을 사용했다. 확장 실행을 활성화하기 위해 조사 Chrome을 같은 프로필로 다시 열고 로컬 extension 폴더를 설치했다. 기존 사용자의 Chrome 확장 파일·설정은 변경하지 않았다.

Chrome 저장소·메시지·서비스 워커를 대체하지 않았다. 실제 확장 팝업과 실제 `START` 메시지로 작업을 실행했다. 빕스 사전 설정에서는 첫 진입 → 총인원 → 날짜·시간 → 팝업에서 인원 구성 저장 후 다음 → 최종 경로 기록을 실제 사이트에서 확인했다. 나머지 상품의 복수 선택·수량 값은 이전 실제 화면 조사에서 명시적으로 지정한 검증값을 사용했다. 사용자의 예약 선호로 간주하지 않았다.

| 상품 | 실제 재검증 일정 | 확인 결과 | 최종 클릭 |
| --- | --- | --- | --- |
| 빕스 | 10/19 14:30, 2명 | 저장한 성인 2명 구성 적용. 최종 설정 없이 확인 목록 4개·필수 동의 자동 선택. 사전 기록 2단계 대조 완료 | 0 |
| 벨포인트의원 | 11/4 16:00 | 첫 화면 단일 필수 옵션은 별도 설정 없이 처리. 최종 시술·내원 경로는 저장한 복수 선택값 적용 | 0 |
| 도심속그릴 | 10/20 12:00, 2명 | 이용료 수량 2와 최종 필수 입력 3개·동의 적용. 결제 전에 중지 | 0 |
| 비욘더팜 | 10/19 19:00 | 텐트 1·추가 인원 2·필수 체크 3개와 나머지 추가 수량 0을 독립 적용. 빈 최종 설정 저장 없이 진행. 화면의 오후 7시 대조 후 결제 전에 중지 | 0 |

사용자가 제보한 빕스 10/16 18:00, 성인 2·청소년 1명 최종 링크에서도, 작업·최종 설정이 없는 상태로 실제 설치 확장이 확인 4개와 동의 1개를 자동 처리하는 것을 별도로 확인했다.

모든 최종 버튼에는 검증용 클릭 차단을 추가했고 클릭 이벤트를 계수했다. 실행 설정도 `autoConfirm:false`였다. 실제 예약·결제·접수 성공은 검증하지 않았다. 로그인 프로필과 예약자 정보는 조사 자료에 포함하지 않았다. 공개 확인 항목만 촬영한 증거는 저장소 밖에 보관했다.

## 재현 검사와 리뷰

- Node 테스트 93개: 설정 검증·값 보존·단계별 준비 상태·새 단계/순서 변경 중지·단일/복수 선택 분기·원자적 신청 잠금.
- 문법 검사 통과.
- 공개 DOM 브라우저 재현 검사 25개: 필수 단일 확인·미선택 체크·복수 목록 발견/지정·팝업 표시/저장·항목 변경·지연 렌더·최신 선택 시간 불일치·결제 중지.
- 실제 설치 확장 재현 검사 6개: 같은 제목의 중간 수량 화면 2개 → 복수 선택/동의가 있는 최종 화면. 실제 팝업·저장소·서비스 워커로 설정 저장·다음·전체 경로 감시를 실행했다. 텐트 1과 인원 2를 구분하고 주소가 수량 변경 때 갱신되어도 적용했다. 자동 신청을 켠 가상 결제 화면에서 클릭 0회.

위의 2개 중간 화면 경로는 가상 사이트 재현이며 실제 네이버 상품의 다중 중간 화면을 추가로 발견했다는 뜻이 아니다. 실제 네 상품의 경로와 별도로 구분한다.

자체 코드 리뷰에서 이전 실행의 단계 기록 초기화, 동일 제목 단계 분리/기존 설정 호환, 경로 기록과 저장값 분리, 저장한 경로 밖의 과거 단계 설정 보존, 문자열 자동 신청 설정 거부, 최종 시간 조회 시점, 설정 불러오기 전 다음 버튼 비활성화를 확인·보완했다.

지원하는 DOM 구조와 현재 네 경로를 검증했다. 모든 네이버 업종·조건 분기를 검증한 것은 아니다. 항목과 선택지까지 완전히 같은 중간 화면을 사이트가 구분 가능한 표식 없이 반복하면 추가 대응이 필요하다. 구분 실패·새 단계·저장값 적용 실패 시 원인을 표시하며 중지한다. 조건에 따라 경로가 달라지면 해당 조건으로 다시 사전 설정한다.
