# 사용 흐름 검토

2026-10-13, 0.1.24 기준. 팝업을 브라우저에서 열어 화면을 확인하고, 사전 설정 → 중간 항목 저장 → 최종 항목 저장 → 재열기 → 감시 시작 흐름을 재현했다. 실제 네이버 로그인 세션에서 네 상품의 전체 예약을 다시 실행한 결과는 아니다.

## 유지하는 것이 좋은 부분

- 희망 날짜는 하나로 시작하고 필요할 때 추가하는 방식.
- 시간 조건을 전체/특정 시간/이후/범위로 구분하는 방식.
- 현재 단계 자동 읽기와 실패 시에만 나오는 `다시 읽기`.
- 필수 항목이 하나뿐이면 자동 처리하고, 실제 선택이 필요한 항목만 사용자가 저장하는 방식.
- 날짜·시간 복원, 상품별 필수 입력 저장, 최근 로그 10개 제한.
- 신청 버튼과 결제 버튼을 구분하는 동작.

## 자동 화면 인식의 확인 범위

기존 네이버 달력·식당 위젯은 기본 인식을 유지한다. 추가 자동 저장은 사용자가 선택한 버튼에서 날짜 전체나 시간을 나타내는 속성과 유일한 버튼을 확인하는 방식이다. 고정된 `16일` 셀 위치를 다른 날짜에도 재사용하지 않는다. 날짜·시간 의미가 없는 임의의 HTML까지 자동 분석하는 기능은 아니다. 다른 달로 이동하는 동작과 완전히 다른 최종 신청 화면도 각각 확인이 필요하다.

후속 개선에서는 `설정 저장됨`과 `현재 예약 화면에서 적용 확인됨`을 구분하되, 평소에는 한 줄의 준비 상태로 표시하는 것이 좋다. 사용자가 내부 구조를 설정할 필요는 없지만, 실제로 확인하지 않은 경로까지 예약 가능하다고 표시해서는 안 된다.

## 추천 적용 순서

먼저 상단 상태/중지와 예약 방식 표시를 개선한다. 그다음 현재 단계만 보이도록 설정 화면을 줄이고 불필요한 인원 체크박스를 제거한다. 마지막으로 조건 미리 선택과 저장된 상품 선택을 추가한다. 이번 릴리스는 고급 설정 제거와 상품별 버튼 자동 저장까지 반영하며, 위 제안으로 기존 화면 전체를 바꾸지는 않는다.
