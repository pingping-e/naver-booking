# 참고 상품 실제 화면 조사

2026-10-06 조사. 대상: https://booking.naver.com/booking/13/bizes/1491414/items/7037654?startDate=2026-10-19

## 직접 확인한 구조
| 대상 | 실제 식별 정보 | 자동 인식 방법 |
| --- | --- | --- |
| 달력 월 | `.calendar_title`, 표시 `2026.10` | 연월 파싱 및 월 이동 |
| 날짜 | `.calendar_table button.calendar_date`, 안의 `.num` | 요청 일자 숫자와 비교 후 selected 확인 |
| 마감 날짜 | `.calendar_date.closed` | 예약하지 않고 마감 기록 |
| 시간 | `.time_area button.btn_time` | 활성 버튼만 조회 |
| 시간 비활성 | `disabled`와 `unselectable` | 후보에서 제외 |
| 오전/오후 | `.time_list` 바로 앞의 `.time_title` | 오전/오후 또는 AM/PM을 반영해 24시간으로 변환 |
| 선택 시간 | `.btn_time.selected` | 선택 결과 확인에 활용 |
| 다음단계 | `button[data-click-code="nextbuttonview.request"]` | CSS 해시 대신 클릭 식별 속성 사용 |
| 다음단계 비활성 | `NextButton__disabled__...` 클래스 | disabled 표시 확인 |

이 상품은 실제 화면에서 `오후` 구역의 `6:00`을 표시한다. 18:00 입력을 단순 문자열 비교하면 놓치므로 구역 정보로 정규화해야 한다. 임의 모양의 NextButton CSS 접미사는 관찰됐지만, 네이버가 자동화 방지 목적으로 주기적으로 이름을 바꾼다는 근거는 확인되지 않았다.

## 기능 확인
- 조회 당시 2026-10-19는 마감이고 시간 버튼은 비활성이었다.
- 확인용으로 2026-10-26을 선택하니 오후 6:00 활성 버튼이 나타났다.
- 날짜·시간 선택 후 다음단계를 직접 눌렀을 때 로그인 페이지로 이동했다. 예약 요청 최종 제출은 하지 않았다.
- 로그인 이후 예약 신청 화면은 인증 없이 조사할 수 없었다. 최종 버튼의 기본 선택자는 임의로 만들지 않았다.
- 상품 안내는 예약 즉시 확정이 아니라 업체 확인 후 확정이라고 명시한다. 신청 후 예약금 2만원 입금 안내가 있으므로 최종 예약 확정과 버튼 클릭은 별개다.

## 콘텐츠 스크립트 실제 DOM 검증
Chromium 151과 일시 설치한 playwright-core로 실제 페이지를 열었다. 확장 콘텐츠 스크립트 그대로 주입하고 Chrome 메시지/저장소 부분은 테스트용 객체로 대체했다. 다음단계 클릭 이벤트를 캡처해 실제 페이지 이동과 제출은 차단했다. 인증서 검증을 비활성화하지 않았으며 환경 제공 프록시 CA를 이용했다.

1. 2026-10-19, 시간 없음: 마감 로그 및 예약 진행 클릭 없음.
2. 2026-10-26, 18:00 지정: 오후 6:00 선택, CLAIM 1회, 다음단계 클릭 이벤트, 종료 메시지.
3. 2026-10-26, 시간 없음: 첫 활성 슬롯 선택, 다음단계 클릭 이벤트, 종료 메시지.

이 확인은 로그인 이후 최종 제출, 실제 예약 성공, 설치된 확장의 전체 런타임 검증을 뜻하지 않는다. 서비스 워커 작업 상태·중복 방지·날짜 순회는 Node 테스트로 별도 확인했다. 다른 상품의 화면 구조는 조사하지 않았다.
