# 네이버 예약 감시 확장프로그램 설계

## 목적과 범위
사용자가 입력한 네이버 예약 상품 URL, 날짜, 우선순위 시간 목록을 감시한다. 로그인된 Chrome의 지정 탭에서 공개 화면 DOM을 확인하고 활성 시간 버튼을 발견하면 예약 진행 버튼을 클릭한다. 기본값은 진행 화면에서 중지하며 최종 확정 자동 클릭은 명시적으로 켜고 선택자를 지정해야 한다. 성공으로 기록하는 것은 버튼 클릭이며 실제 예약 성립은 예약 내역에서 확인한다.

도메인 허용 후 참고 페이지 HTML은 HTTP 200으로 확인했다. 다음단계 버튼과 상품 안내를 확인했으나 달력은 서버 HTML에서 로딩 상태다. headless Chromium은 프록시 인증서 신뢰 오류로 실행 화면 검증을 완료하지 못했다. TLS 검증을 끄지는 않았다. 선택자는 추정 가능한 기본값과 사용자 CSS 설정으로 제공한다. 현재 결과물은 실사이트 검증이 필요한 MVP다.

## 구성
- Manifest V3, 외부 라이브러리와 서버 없는 JavaScript 확장.
- 팝업: URL, 날짜, 시간 목록, 최소 15초 확인 주기, CSS 선택자, 자동 확정 여부 설정 및 시작/중지, 최근 60개 로그.
- 서비스 워커: 지정 탭 생성, storage.local 상태 관리, chrome.alarms 기반 새로고침. Promise 큐로 상태 변경을 직렬화한다.
- 콘텐츠 스크립트: 지정 탭 여부를 워커에 확인하고 DOM 준비를 기다려 날짜 → 우선순위 시간 → 예약 진행 → 선택적 최종 확정을 수행한다.
- 권한: storage, alarms, tabs, 네이버 예약 두 도메인. 로그인 토큰을 읽거나 별도 서버로 전송하지 않는다.

## 상태 및 중복 방지
대기 → 감시 → 예약 진행 잠금 → 종료. 활성 슬롯 발견 시 워커의 CLAIM으로 감시 상태를 원자적으로 예약 진행 상태로 바꾸고 알람을 제거한다. 다른 탭과 오래된 작업 ID는 거부한다. 브라우저 재시작, 탭 닫힘, 다른 경로로 이동, 오류 발생 시 중지한다. 예약 진행 중 페이지가 이동하면 자동으로 후속 화면을 재개하지 않는다. 중복 제출을 피하기 위해 실패 시 재예약하지 않고 사람이 화면을 확인한다.

## 화면 인식
날짜는 정확한 YYYY-MM-DD data-date/aria-label 또는 명시한 CSS 선택자를 사용한다. 참고 페이지의 공개 JS 번들에서 calendar_title/calendar_table/calendar_date/num 구조를 확인하여, 연월 헤더를 읽고 최대 24회 월 이동 후 일자 버튼을 고르는 보조 경로도 구현했다. 헤더를 해석하지 못하면 클릭하지 않는다. 이 보조 경로는 실브라우저 검증 전이다. URL 날짜만으로 선택 성공을 가정하지 않는다. 시간은 HH:mm과 정확히 일치하는 활성 버튼을 순서대로 찾거나 {time} 치환 선택자를 사용한다. 표시되지 않거나 disabled/aria-disabled/inert 버튼은 제외한다. 후보가 여러 개면 자동 선택하지 않고 중지한다. 날짜 선택자의 실제 날짜 일치 및 시간 전환은 실사이트에서 반드시 검증해야 한다. 예약 진행 기본 텍스트는 예약하기, 예약, 다음, 다음단계다. 최종 확정은 기본 추측 없이 명시적 선택자만 사용한다.

## 제약과 검증 계획
Chrome 알람은 절전·탭 정지에 의해 늦어질 수 있어 정확한 초 단위 스케줄을 보장하지 않는다. 감시는 브라우저가 열린 동안만 작동한다. 캡차 우회, 세션 자동 로그인, 약관 자동 동의, 결제정보 입력 기능은 없다. SPA/전체 페이지 전환과 버튼 구조는 네이버 구현에 따라 선택자 조정이 필요하다.

자동 검증은 URL/날짜/시간/확정 설정 검증과 JS 구문 검사를 수행한다. 수동 검증은 로그인 후 날짜와 시간 선택자 확인, 매진 상태 반복 감시, 활성 시간 발견, 중지 및 탭 닫힘, 팝업 재열기, 브라우저 재시작, 예약 진행 후 새로고침 중단을 확인한다. 자동 확정은 승인된 실제 예약 의사가 있을 때만 수행하고 예약 내역에서 결과를 확인한다. Chrome 인증서 신뢰 문제로 실사이트 통합 검증은 아직 완료하지 못했다.

## 0.1.1: 짧은 주기와 전체 시간
시간 목록이 비어 있으면 시간 라벨(HH:mm, h:mm, 오전/오후)을 가진 활성 버튼 중 화면에서 처음 발견한 슬롯을 선택한다. 마감/매진/불가 라벨은 제외한다. 특정 시간 우선순위는 목록을 입력하면 유지한다. Chrome alarms의 최소 주기 제약 때문에 15~29초는 지정 예약 탭의 콘텐츠 타이머로 처리하며 매번 워커가 작업 ID, 탭, 경로, 감시 상태를 다시 검증한다. 확인 작업 도중에는 새로고침하지 않는다. 30초 이상은 기존 알람을 사용한다. 탭 정지, 긴 로딩, 절전에서는 지연되므로 15초의 정밀 스케줄을 보장하지 않는다.
